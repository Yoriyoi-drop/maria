2.1 PIPE UTAMA
Preprocessor → Lexer → Parser → AST → Elaborator → IR → Engine → VCD/FST
Layer tambahan: HIR (lazy elab), MIR (opt), Cache, Diagnostics.
Arsitektur 3-tier (Frontend/AST/Backend) dengan cross-cutting layers.

MASALAH ARSITEKTUR KRITIS:

Arsitektur-01: ⚠️ Tidak ada SSA form — masih open
  Root Cause: IR (crates/maria-ir/src/ir.rs) adalah flat AST-style, bukan SSA.
  Impact: Tidak bisa optimasi global (CSE, DCE, LICM, GVN).
  Severity: Critical
  Fix: Implement SSA-based MIR dengan dominance frontier.
  Complexity: Phase 5-6 (6-12 bulan)

Arsitektur-02: ⚠️ Compiled-code simulation — masih open
  Root Cause: Simulator interpreter-based (evaluate_stmt_block
  men-traverse IR tree di runtime).
  Impact: 10-100x lebih lambat dari Verilator compiled C++.
  Severity: Critical
  Fix: Generate native code via Cranelift/LLVM untuk seluruh
  process body, bukan hanya expression eval.
  Complexity: Phase 7-8 (12-18 bulan)

Arsitektur-03: ⚠️ Engine single-threaded — masih open
  Root Cause: EventRegion Active/Inactive diproses dalam satu thread.
  Rayon hanya dipakai di DAG layer untuk Combinational processes.
  Impact: Amdahl's law — single-thread serial fraction ~80%.
  Severity: Critical
  Fix: Region-level parallelism, multi-threaded delta scheduler,
  lock-free signal state.
  Complexity: Phase 6-8 (12-18 bulan)

Arsitektur-04: ⚠️ Signal state Mutex — masih open
  Root Cause: state.signals adalah Vec<LogicVec> tanpa concurrent access.
  DAG parallel clone entire snapshot tiap cycle.
  Impact: Copy overhead O(N*M) untuk N signal M processes per cycle.
  Severity: High
  Fix: Row-based signal storage dengan fine-grained locking atau
  read-copy-update (RCU).
  Complexity: Phase 4-5

Arsitektur-05: ✅ Hierarchical timing wheel — FIXED
  Root Cause: events: Vec<Vec<RegionEvent>> dialokasikan apriori
  sebesar max_time+1. Drain/filter tiap delta siklus O(E).
  Impact: Memori O(max_time * events_per_time). Query overhead O(E)
  per delta cycle. Untuk sim 1M cycle, memori event queue bisa
  mencapai GB.
  Fix: Hierarchical timing wheel dengan bucket-based scheduling O(1)
  per event. Sub-offset remainder untuk cascade precision.
  Complexity: Phase 4-5
  STATUS: ✅ FIXED — 12 unit tests, 1160 total pass, 0 regression

Arsitektur-06: ⚠️ Elaborator monolithic — masih open (partial: refactor ke submodule)
  Root Cause: Semua logika elaborasi (signal resolution, type
  checking, instance flattening, parameter override, generate
  unrolling) dalam satu file.
  Impact: Tidak bisa parallel elaborate. Testability rendah.
  Memori tinggi — elaborator hold full AST + IR concurrently.
  Severity: High
  Fix: Modular elaborator dengan pass architecture (like
  LLVM PassManager).
  Complexity: Phase 3-4

Arsitektur-07: ⚠️ Tidak ada persistent design database — masih open
  Root Cause: Setiap compile dari awal. Cache file-level, bukan
  structural.
  Impact: Cold compile untuk OpenTitan-scale perlu ulang semuanya.
  Tidak ada incremental type resolution.
  Severity: High
  Fix: Implement design database (like Libero's .db atau
  VCS's .syn/.simv).
  Complexity: Phase 5-6

2.2 SCHEDULER ARCHITECTURE

Scheduler mengklaim 12-region IEEE 1800 compliance, dan implementasi
di core.rs menunjukkan ke-12 region diproses dalam loop. Namun:

Sched-01: ✅ Postponed region — FIXED (ditambahkan ke IEEE_REGIONS)
   Root Cause: $strobe dan $monitor dipanggil SETELAH delta loop.
   Impact: IEEE 1800-2017 Section 4.5.4 violation.
   Severity: High
   Fix: EventRegion::Postponed ditambahkan, diproses 1x per time step.

Sched-02: ✅ NBA commit — FIXED (di Nba region handler)
   Root Cause: Sebelumnya commit_nba() hanya di Reactive branch.
   Impact: NBA region di-loop sebelum Reactive → commit 1 region delay.
   Severity: High
   Fix: Commit NBA dipindahkan ke EventRegion::Nba region handler.
   STATUS: ✅ FIXED — self.commit_nba() di EventRegion::Nba (core.rs:1344)

Sched-03: ✅ Delta limit warning — FIXED
   Root Cause: if delta_count > 10_000_000 { return Err }
   Impact: Debugging zero-delay loops impossible.
   Severity: Medium
   Fix: Warning setiap 100K delta, configurable max 20M.

Sched-04: ✅ Preponed snapshot per delta — FIXED
   Root Cause: Snapshot di-update per cycle bukan per delta.
   Impact: Edge detection pakai snapshot stale di multi-delta.
   Severity: Critical
   Fix: signal_snapshot di-refresh setiap delta cycle.

2.3 MEMORY ARCHITECTURE

Mem-01: ⚠️ All signals in memory — masih open (partial: signal history VecDeque)
  Root Cause: state.signals: Vec<LogicVec> untuk semua signal
  di top-level flattened design. History: HashMap per signal.
  Impact: 1M signal x 1KB avg → 1GB base. History unbounded
  (max 100K entries per signal).
  Severity: Critical
  Fix: Signal paging, sparse storage, compression. History
  offload ke disk.

Mem-02: ⚠️ No memory budget — PARTIAL: CacheManager LRU added, tapi tanpa max budget
  Root Cause: CacheManager, HirCache, AstCache grow without
  limit. No LRU eviction.
  Impact: Memory leak di long-lived compile daemon.
  Severity: High
  Fix: Implement memory budget dengan LRU eviction per cache.

Mem-03: ⚠️ mmap semua files — masih open
  Root Cause: FastLexer + MmapFile mmap seluruh file sebelum
  diproses. Tidak ada limit jumlah file concurrent.
  Impact: 100K files x 10KB average = 1GB virtual address.
  File >4GB bisa exhaust address space di 32-bit.
  Severity: Medium
  Fix: Stream processing dengan read-ahead buffer, mmap
  windowing.

═══ 2.4 JIT ARCHITECTURE ═══

JIT-01: ⚠️ JIT hanya expression — masih open
  Root Cause: CompiledExpr hanya compile binary/unary/const ops.
  Evaluate_stmt_block tetap interpreted.
  Impact: Speedup minimal di simulation (Amdahl: bottleneck di
  interpreter).
  Severity: Critical
  Fix: Compile seluruh process body ke native code. Generate
  state transitions natively.

JIT-02: ⚠️ JIT tidak cache di disk — masih open
  Root Cause: JITCache in-memory only. Cold sim selalu
  recompile.
  Impact: Startup lambat, terutama untuk large designs.
  Severity: High
  Fix: Persistent JIT cache dengan content-addressable storage.

═══ 2.5 PARALLEL ARCHITECTURE ═══

Par-01: ⚠️ Work-stealing scheduler — masih open (file ada, tidak terintegrasi)
  Root Cause: Scheduler/work_stealing.rs dibuat tapi tidak
  diintegrasikan ke SimulationEngine.
  Impact: CPU utilization rendah saat sim.
  Severity: High
  Fix: Port task scheduler ke simulation engine untuk
  event-driven parallelism.

Par-02: ⚠️ DAG hanya combinational — masih open
  Root Cause: Sequential processes (AlwaysFF, AlwyasWithDelay)
  bypass DAG dan jalan sequential.
  Impact: Sebagian besar processes di desain sinkron —
  paralelisme rendah.
  Severity: High
  Fix: Clock-domain-based parallel scheduling untuk sequential
  processes.

Par-03: ⚠️ Clone bodies di parallel eval — masih open
  Root Cause: Setiap DAG layer, seluruh body proses di-clone.
  Signal snapshot di-clone.
  Impact: Memory thrashing untuk body besar. Allocator pressure.
  Severity: High
  Fix: Arc-based process body sharing, differential snapshot.

PROYEK RISET — BELUM SIAP TAPE-OUT KOMERSIAL
============================================

Maria adalah proof-of-concept arsitektur simulator HDL modern
dalam Rust yang menunjukkan pemahaman mendalam tentang IEEE 1800
dan teknik compiler modern. Namun untuk digunakan dalam tape-out
chip komersial (ASIC/SoC skala enterprise), terdapat gap
fundamental yang membutuhkan investasi 5-10 tahun dan puluhan
juta dolar untuk mencapai paritas dengan Verilator/VCS/Questa.

ARGUMEN TEKNIS RINCI:

1. SIMULATION PERFORMANCE GAP
   Interpreter-based design → 50-100x lebih lambat dari Verilator
   compiled-C++ dan 20-50x lebih lambat dari VCS native.
   Untuk regression 10K tests x 1M cycles = tidak feasible.

2. COMPILER OPTIMIZATION ABSENCE
   Tidak ada SSA, CSE, DCE, LICM, atau optimization pass apapun.
   MIR opt hanya 142 lines. Ini membuat Maria setara compiler
   undergraduate project, bukan production EDA tool.

3. VERIFICATION INFRASTRUCTURE GAP KRITIS
   Tidak ada code coverage = tidak bisa sign-off tape-out.
   Tidak ada UCDB/UCM coverage database = coverage tidak bisa
   dianalisis multi-run. Constraint solver rejection sampling =
   tidak bisa handle complex constraints.

4. LANGUAGE SUPPORT GAP FATAL
   Dynamic arrays, associative arrays, queues — semua tidak
   support. Ini blocking untuk testbench development.
   uvm_callback, uvm_reg, uvm_tlm — tidak ada. Semua UVM VIP
   komersial depend on these.

5. ENTERPRISE INFRASTRUCTURE KOSONG
   Tidak ada CI/CD, regression management, distributed build,
   license management, IP protection, API, scripting, atau
   tool integration. This is not deployable in any
   professional engineering team.

6. EDA ECOSYSTEM ISOLATION
   No VPI/PLI = tidak bisa integrasi dengan Verdi, SpyGlass,
   JasperGold, PrimeTime, atau EDA tool apapun.
   No FSDB = waveform tidak bisa dibuka di Verdi.
   No UCDB = coverage tidak bisa di-merge.

7. TESTING INFRASTRUCTURE RAPUH
   6 pre-existing test failures = confidence rendah.
   Stress tests ignored = large design paths untested.
   No sanitizer tests = memory safety unverified.

8. IDE/LSP ABSOLUTELY ABSENT
   Developer productivity untuk SV engineers sangat bergantung
   pada LSP. Tanpa LSP, Maria tidak bisa diadopsi di tim
   engineering profesional.

CORE STRENGTHS (pengakuan):

+ Arsitektur modular bersih dengan cross-cutting layers
+ Incremental compile sangat cepat (~0.45s untuk 10K modules)
+ SIMD lexer menunjukkan pemikiran performa modern
+ Zero-deallocation sim arena — teknik memory management baik
+ IEEE 1800 12-region scheduler — implementasi paling correct
  di open source
+ Cranelift JIT integration — langkah tepat meski masih early
+ String interning O(1) dengan DashMap — scalable
+ Testing cukup comprehensive (951 test functions)
+ Dokumentasi arsitektur excellent (DESIGN.md 1975 lines)
+ Arena allocator suite (bump, typed, slab, pool)
+ Cache Manager dengan content hashing
+ Multiple frontend (CLI + Tauri GUI)
+ Open source MIT license

RECOMMENDATION:

Maria harus di-reposisi sebagai:
1. Fast prototyping/syntax-checking tool untuk SV engineers
2. Educational platform untuk memahami simulator architecture
3. Research platform untuk compiler optimization pada HDL
4. Reference implementation untuk IEEE 1800 scheduling
